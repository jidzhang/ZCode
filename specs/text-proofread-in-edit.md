# 消息编辑窗口「纠错」（打字错别字纠正）

## 背景与目标

用户发出的消息可点「编辑」进入行内编辑窗。人手打字常出明显错别字（同音/形近/选词失误），
多数时候不影响模型理解，但偶尔会误导任务。需要一个人工触发的纠错入口：拿当前模型、以最低
思考成本，只纠正这段文字里的明显错别字/笔误，用户自己看一眼，可手改也可直接发送。

**本功能只建议、永不替用户改写或发送**：纠错是一次独立的辅助模型调用，结果只回填编辑框，
发送仍由用户手动完成；不满意可用编辑器原生 `Ctrl+Z` / `Cmd+Z` 一步撤销。

## 入口与交互

- 位置：行内编辑窗底部按钮区。顺序为 `[纠错] [取消] [工作区回卷] [发送]`——
  纠错按钮排在取消按钮**之前**；工作区回卷按钮保持原位置不动。
- 文案：按钮名「纠错」（英文 `Fix typos`），图标按钮 + 悬浮提示 + `aria-label`。
- 触发：仅手动点击。**任何自动触发（发送前检查、输入实时检查）都不做。**
- 字数门槛：编辑框文字 `trim()` 后不足 5 个字符时，点击**静默无效果**——
  不进入 loading、不弹任何提示、不发请求。
- 等待态：请求期间按钮显示 spinner 且禁用，不影响取消/发送按钮以外的编辑。

## 调用链路与所有权

```
UI 编辑行按钮
  → useZCodeAgentService(workspacePath, remoteSessionId, workspaceIdentity)
  → zcodeAgentService.proofreadText({ text, selection })
  → services/text-proofread（contract.ts 契约 + textProofread.ts 实现：
      system prompt + 输出清洗 + 安全闸 + 档位兜底）
  → zcodeAgentService.generateWorkspaceText（协议 workspace/generateText，
      querySource = "text_proofread"）
  → bootstrap server-operations.generateWorkspaceText（复用活跃 workspace App，无会话则临时 App）
  → core runtime generateWorkspaceText
  → auxiliaryModelOptions 绑定最低公开档 + 输出预算上限
```

- **无会话、无上下文、不进对话历史、不建 turn**：只发送两段消息（system prompt + 原文一处）。
  与「生成提交信息」同一个 workspace 级通道，不新增协议方法。
- 唯一 owner：编辑框草稿仍是 UI 局部状态；服务端不保存纠错结果、不写会话。切换/取消编辑
  即丢弃。
- 幂等/并发：每次点击独立请求；重复点击在等待态被禁用。不做结果缓存。

## 模型与思考档位策略

- 模型 = 会话当前模型（`rowContext.modelSelectionView.effectiveSelection`，
  缺失时 `preferredSelection`）；不另挑模型、不读全局默认。
- 主尝试档位 = 模型公开档位列表的**最低项**（`auxiliaryModelOptions`，与标题生成、
  提交信息生成同一约定），输出预算上限 5000 token。
- **档位被拒的兜底（不静默藏着）**：core 已对"档位被上游拒绝"产出点名错误
  （`specs/reasoning-degrade-retry.md`）。命中该错误时，用**会话当前选择的档位**
  重试一次（该组合在本会话已跑通，通常可用），成功则：
  - 日志 `warn` 记录 `text_proofread.reasoning_fallback`；
  - UI 轻提示「最低思考档不可用，已改用当前对话档位纠正」。
    不改会话持久化的档位设置——只是这一次辅助请求换档，配置问题仍暴露给用户。
- 兜底条件不满足（两档相同、无 fallback 选择）或兜底仍失败：不继续重试。
- 非档位错误（网络、模型不可用、超时）：不重试，直接失败。

## 保守纠错约定

system prompt 硬约束（只喂原文，不给上下文）：

- 只改明显的错别字与明显的输入笔误；不确定是否是错别字时保持原样。
- 保持原意、原措辞、语气与语言，不重写、不润色、不扩写、不缩写、不翻译。
- 保留代码标识符、文件路径、URL、命令、专有名词、数字与刻意用法。
- 保留换行结构；只输出改后正文，无解释、无引号、无标签、无代码围栏。

## 安全闸（输出不合格一律丢弃，草稿不变）

1. `trim()` 后与原文相同 → 视为「未发现明显错别字」，提示后不改动。
2. `finishReason` 为长度截断（`length` / `max_tokens`）→ 丢弃（截断结果不可用）。
3. 清洗（去围栏/标签/包裹引号、去首尾空白）后为空 → 丢弃。
4. **改后正文与原文的字符数相差超过 10 个 → 丢弃**。纠错只应是等长或近似等长的替换；
   长度大幅变化说明模型在改写，不能采纳。
5. 丢弃统一提示「纠错未生效」，编辑框保持用户原文。

## 落地与撤销

- 结果经 `inputApiRef.current.setTextWithUndoStep(corrected)` 直接替换编辑框文字（用户选择的方案）。
- 该入口在 `editor.update` 内重建文本节点，并在通用程序化标记之外附加 Lexical
  `HISTORY_PUSH_TAG`，强制成为**独立历史步**、不与紧邻打字合并；因此
  `Ctrl+Z` / `Cmd+Z` 一步回到纠错前原文。**不加独立回退按钮。**
- 纠错成功后编辑框内容照常走 `onChange → setDraft`，后续手动发送/取消语义完全不变。

## 验收场景

1. 编辑框输入 ≥5 字且含明显错别字 → 点「纠错」→ 返回纠正文本并替换；`Ctrl+Z` 一步恢复原文。
2. 输入不足 5 个字符 → 点「纠错」→ 无任何请求、无 loading、无提示。
3. 原文没有明显错别字 → 结果与原文一致 → 提示「未发现明显错别字」，编辑框不变。
4. 模型返回长度与原文相差 >10 字 → 丢弃 + 提示，编辑框保持原文。
5. 模型返回被截断（finishReason=length）→ 丢弃 + 提示，编辑框保持原文。
6. 最低档被上游拒绝（如网关不支持 `disabled→none`）→ 用会话当前档位重试一次：
   成功则替换并给出换档提示；仍失败则提示失败，编辑框不变。
7. 网络错误/模型不可用 → 提示失败，编辑框不变，不重试。
8. 工作区没有有效模型选择 → 提示失败，不发请求。
9. 运行中的任务同样可点「纠错」：workspace 级独立请求，不打断当前 turn、不影响排队输入。
10. 既有发送/编辑/取消/工作区回卷行为零变化；按钮不出现时（如只读场景）编辑窗与现状一致。

## 明确不做

- 上下文纠错（把会话历史喂给纠错模型）。
- 纠错预览/diff 对比层（用户选择直接替换 + 原生撤销）。
- 自动触发：发送前检查、输入实时纠错。
- 专用的纠错小模型或跨模型选择；始终用会话当前模型。
- 独立的回退按钮或纠错历史。
